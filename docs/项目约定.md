# 项目约定

> 建立日期：2026-08-12
> 适用范围：本项目 `d:\Dev\Projects\my_project_offermaster`（含 Java / Python / 前端 / 配置 / 文档）

## 一、目的

记录项目每一次修改的背景、内容与效果，保证项目变更可追溯、可复盘、可交接。

## 二、核心约定：修改必记录

**每次修改项目后，必须向 `docs/变更记录.txt` 追加一条变更记录。**

### 适用范围

- 任何对仓库代码、配置、文档（含本约定自身）的修改，一律记录。
- 纯格式化、临时草稿、探索性且未落地的改动不强制记录（由执行者判断，能记则记）。

### 记录字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 修改原因 | 是 | 为什么改：需求、bug、重构、文档等背景 |
| 修改内容 | 是 | 改了什么：文件 + 关键改动点 |
| 解决了什么 | 是 | 效果：修复了什么问题 / 达成了什么目标 |
| 涉及文件 | 否 | 本次改动涉及的文件路径列表 |
| 验证结果 | 否 | 如何验证、验证结果如何 |
| 备注 | 否 | 其他补充说明 |

### 记录规则

- 记录文件：`docs/变更记录.txt`。
- 追加式：新条目追加到**文件末尾**，保持时间正序。
- 编号递增：从 `#001` 起，依次递增，不重复、不覆盖。
- 合并记录：一次多文件的改动记作**一条**记录，不逐文件拆分。
- 记录时机：修改完成并通过验证后追加。

## 三、条目格式模板

```
----------------------------------------------------------------
变更 #N  日期：YYYY-MM-DD HH:mm
【修改原因】……
【修改内容】……
【解决了什么】……
【涉及文件】……
【验证结果】……
----------------------------------------------------------------
```

其中「涉及文件」「验证结果」无内容时填「无」或「略」。

## 四、执行人

- AI 助手：在每次修改任务收尾时，自动按本约定追加记录。
- 人工修改：由修改者按模板手动追加。

## 五、相关文件

- `docs/项目约定.md`：本约定文档。
- `docs/变更记录.txt`：变更记录文件（唯一记录处）。
