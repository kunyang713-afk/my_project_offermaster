变更 #002  日期：2026-08-12
【修改原因】阶段二 M6「历史摘要压缩节点（防上下文膨胀）」落地：`final_report` 以全量 transcript 喂 LLM，长面试（3~5 题 × 追问）下 token 可达数万，存在报告质量下降/超限风险。
【修改内容】新增 `compress_history` 节点：每道主主题结束（`next_question` 判定需换题）时，把该主题对话经 `llm.compress_history()` 增量合并进 `state.conversation_summary`，并以 `{"__replace__": []}` 整体裁剪 `state.messages`；`messages` reducer 由 `operator.add` 改为自定义 `reduce_messages`（普通 list 追加 / 替换信号裁剪双语义）；最后一题不压缩，`final_report` 改用「历史摘要 + 最近一题完整对话 + 全量 assessments」生成报告。`graph.py` 注册新节点（Command 路由，无新边）。README 能力/验收、design-decisions M6 落地注记同步更新。
【解决了什么】面试 State 的 messages 严格有界（只保留当前题窗口），`conversation_summary` 增量记录历史；终局报告不再吃全量 transcript，从根上控制喂给 LLM 的 token 量，防上下文膨胀；Java 协议与消息落库（Java 侧权威）不受影响。
【涉及文件】ai-brain/app/state.py、ai-brain/app/llm.py、ai-brain/app/nodes.py、ai-brain/app/graph.py、README.md、docs/design-decisions.md
【验证结果】py_compile 通过；临时冒烟脚本（mock LLM/检索 + MemorySaver）验证：2 题流程换题后 summary 非空、messages 裁剪为只剩新题，收尾时 messages 保留最后一题完整轮次、final_report 正常产出；IDE 诊断无告警。

变更 #003  日期：2026-08-12
【修改原因】M6 压缩触发策略由「每轮自动触发（换主题即压缩）」调整为「上下文空间溢出触发」：每轮压缩造成无谓的 LLM 调用与摘要覆盖，短面试本不需要压缩；按预算阈值按需触发更符合「防上下文膨胀」本意。
【修改内容】`next_question` 改为溢出判定路由：`messages` 总字符数 > `history_max_chars`（新增配置，默认 8000，config/.env 可调）才 goto `compress_history`，否则直接 generate_question / final_report（不压缩）。`compress_history` 按新状态字段 `topic_start`（`generate_question` 出题前写入）划分「旧主题 = messages[:topic_start]」压缩进 `conversation_summary`、「最近主题 = messages[topic_start:]」原样保留并裁剪 messages；压缩后按是否问完路由 final_report / generate_question；`topic_start == 0`（单主题即超预算）时整体压缩清空作兜底。README / design-decisions 的 M6 描述同步改为溢出触发语义。
【解决了什么】未超预算的面试全程零压缩零额外 LLM 调用；溢出时只压缩旧主题、保留最近主题原文供报告引用；State 与 final_report 消费的上下文仍受预算约束，防膨胀目的不变。
【涉及文件】ai-brain/app/config.py（新增 history_max_chars）、ai-brain/app/state.py（新增 topic_start）、ai-brain/app/nodes.py（next_question/compress_history/generate_question 改造）、README.md、docs/design-decisions.md
【验证结果】py_compile 通过；冒烟脚本（mock LLM/检索 + MemorySaver）覆盖两场景：不溢出时无压缩调用、messages 全量保留、报告正常；溢出时旧主题入 summary、messages 只留最近主题、topic_start 归零、报告正常；IDE 诊断无告警。

变更 #005  日期：2026-08-12
【修改原因】浏览器携带过期/失效 token 点击「开始面试」时，Spring Security 对未认证请求返回 403 且无 JSON 错误体（前端只显示 "HTTP 403"），且页面加载时仅凭 localStorage 存在 token 即显示"已登录"、不校验有效性，鉴权失效体验差。
【修改内容】1) 后端 `SecurityConfig` 新增 `exceptionHandling` 的 `AuthenticationEntryPoint`：未认证/无效 token 统一返回 401 + `{"error":"未登录或登录已过期"}`（替代默认 403）；2) 前端 `api()` 捕获 401/403 时调用新增 `logout()`——清空 token/sessionId/localStorage 并切回登录卡片、提示重新登录；3) 前端源文件 `frontend/index.html` 与后端静态 `backend-java/src/main/resources/static/index.html` 同步（保证源码与运行版一致）。
【解决了什么】失效 token 场景由"403 裸报错"变为"401 + 明确错误信息 + 自动登出回到登录页"；语义正确（未认证=401），前端可自动恢复登录态，避免用户困惑；同时前端源/静态两份文件保持一致，避免后续构建覆盖丢失该修复。
【涉及文件】backend-java/src/main/java/com/offermaster/config/SecurityConfig.java、frontend/index.html、backend-java/src/main/resources/static/index.html
【验证结果】重新 mvn package 并重启后端后实测：无 token → 401 + JSON 错误体；伪造 token → 401 + JSON 错误体；新注册有效 token → 200 正常返回首题；页面同时含微信风格与 401/403 自动登出逻辑。

变更 #009  日期：2026-08-12 23:30
【修改原因】面试全链路（浏览器→Java→AI-brain）此前为阻塞式 HTTP 调用，用户提交回答后需等待 LLM 全部跑完才能看到下一题/报告，期间页面无任何反馈，体验差。需引入 SSE 流式返回，让用户实时看到 AI 各阶段进度（正在总结简历/正在生成题目/正在评估回答…）与最终结果。
【修改内容】
1) AI-brain 侧（`ai-brain/app/graph.py`、`ai-brain/app/api.py`、`ai-brain/app/checkpointer.py`）：
   - `checkpointer.py` 新增 `get_async_checkpointer()` 返回 `AsyncPostgresSaver`（同步 `PostgresSaver` 不实现 async 接口，`astream_events`/`aget_state` 必须搭配异步 checkpointer）；与同步 checkpointer 共享同一组 Postgres checkpoint 表，thread_id 状态互通。
   - `graph.py` 新增懒加载 `_async_app`（`builder.compile(checkpointer=AsyncPostgresSaver)`）、`NODE_LABELS`（7 个 LLM 重节点的中文进度文案）、`_aiter_events()`（过滤 `on_chain_start` 事件仅产出有展示价值的节点）、`stream_start()` / `stream_answer()`（async generator，产出 stage/result 事件，流结束后用 `aget_state` 读取最终结果）。
   - `api.py` 新增 `/ai/interviews/{id}/start/stream`、`/ai/interviews/{id}/answer/stream` 两个 SSE 端点（`StreamingResponse` + `text/event-stream`，手写 `event: type\ndata: json\n\n` 帧，不引入 sse-starlette）；Windows 本地开发需切换 `WindowsSelectorEventLoopPolicy`（psycopg 异步不兼容 ProactorEventLoop），Linux/Docker 无此问题。
   - 原有阻塞端点 `/start`、`/answer` 零改动，保留兼容。
2) Java 侧（`AiStreamClient.java`、`InterviewService.java`、`InterviewController.java`、`InterviewSessionRepository.java`、`MessageRepository.java`、`ReportRepository.java`、`GlobalExceptionHandler.java`）：
   - 新增 `AiStreamClient`：JDK `HttpClient`（强制 `HTTP_1_1`，避免默认 HTTP/2 Upgrade 导致 uvicorn 返回 422）异步消费 AI-brain SSE 流，按行解析 `event:`/`data:` 帧并回调 `onEvent(eventType, jsonNode)`；非 200 响应读取 body 打印日志并回 error 事件；流结束发 `done` 事件 + `emitter.complete()`。
   - `InterviewService` 新增 `startStream()` / `answerStream()`：与阻塞路径业务语义一致（脱敏/建会话/落消息/落报告/会话 COMPLETED），但用 `CompletableFuture` 门闩替代同步块实现跨线程串行化（SseEmitter 在异步线程完成）；不启用 `@Transactional`（事务与请求线程生命周期冲突），`@Modifying` 查询用 `TransactionTemplate` 编程式事务包裹；失败时回删 USER 消息保证同 turnId 可重试。
   - 三个 Repository 新增投影查询（`@Query` 显式 select 单列），避免无外层事务时 Hibernate 物化 `@Lob` 字段报 `Unable to access lob stream`：`InterviewSessionRepository.findStatusByIdAndUserId` / `updateStatus`、`ReportRepository.findSummaryBySessionId`、`MessageRepository.findLastContentBySessionIdAndRole`（native SQL）。
   - `InterviewController` 新增 `POST /api/interviews/stream/start`、`POST /api/interviews/{id}/answer/stream`（`produces = TEXT_EVENT_STREAM_VALUE`，`SseEmitter(0L)` 永不超时）。原有阻塞端点保留。
   - `GlobalExceptionHandler` 新增 `log.error("Unhandled exception", ex)` 打印堆栈（便于排障）。
3) 前端（`frontend/index.html` + `backend-java/src/main/resources/static/index.html` 同步）：

变更 #011  日期：2026-08-12
【修改原因】用户反馈「/ask 前端好像并没有 stream 那种流式返回啊，ai 回复是直接蹦完的」——#009 仅推送阶段进度（stage）+ 最终结果（result），AI 文本整体一次性出现，没有逐字/逐 token 的流式观感。经与用户确认选择「真流式 + 打字机」混合方案：LLM 生成过程按 token 真流式推送，结构化整体返回（出题/报告）用前端打字机逐字渐进渲染。
【修改内容】
1) AI-brain 侧：
   - `ai-brain/app/llm.py`：三个非结构化 LLM 函数（`summarize` / `generate_followup` / 历史压缩）给 chat 调用加 `.with_config({"tags": ["stream:summarize"]})` / `["stream:follow_up"]` / `["stream:compress_history"]`，tags 沿调用链传播到 `on_chat_model_stream` 事件；结构化函数（plan_focus/generate_question/evaluate/final_report）不加 tag，保持整体返回 + 前端打字机。
   - `ai-brain/app/graph.py`：`_aiter_events` 在原有 `on_chain_start`（stage）基础上，新增监听 `on_chat_model_stream` 事件，通过事件 tags 匹配 `stream:` 前缀产出 `{"type": "token", "data": {"node": <节点名>, "token": <增量文本>}}` 事件（从 chunk.content 提取，兼容 str/非 str 类型静默跳过）。
2) Java 侧（`InterviewService.java`）：`handleStartEvent` / `handleAnswerEvent` 新增 `token` 事件类型分支，原样转发 `forward(emitter, "token", payload)`，实现 Java 代理层对 token 事件的无损透传。
3) 前端（`frontend/index.html` + `backend-java/src/main/resources/static/index.html` 同步）：
   - `parseSseFrame` 新增 `token` 事件分发 → `handlers.onToken(data)`。
   - `streamPost` 新增 `onToken` 回调参数。
   - `startInterview()` 的 onResult 改为 `typeMsg('assistant', d.question)` 打字机渲染（出题为结构化整体返回）；onToken 对 summarize/compress_history 静默（内部处理，不展示）。
   - `doAnswerStream`：onStage 显示「AI 正在思考…」；onToken → `onAnswerToken`（仅 follow_up 节点真逐 token 追加到流式气泡 `streamingRow`）；onResult 收到 done 时清理流式气泡并 `showReport`（summary 打字机渲染），收到追问时若已有流式气泡则用完整文本覆盖（防 token 遗漏）否则 `typeMsg` 打字机渲染。
   - 新增 `typeMsg(role, text)` 打字机函数（setInterval 每次 +2 字、25ms，完成后清除定时器、自动滚动到底）；`showReport` 的 summary 用打字机渲染后 `renderReportItems` 渲染错误题项。
   - 网络中断恢复：`answerError` 不回滚 turn、不删除用户气泡，显示「重试」按钮（`retryAnswer` 用相同 turnId 重发走幂等）。
【解决了什么】前端实现「真流式 + 打字机」混合流式观感：追问（follow_up）为 LLM 逐 token 真流式逐字出现，出题/终局报告 summary 为整体返回后打字机逐字渐进显示；AI 回复不再「直接蹦完」。summarize/compress_history 等内部处理的 LLM 调用不污染界面。
【涉及文件】ai-brain/app/llm.py、ai-brain/app/graph.py；backend-java/.../service/InterviewService.java；frontend/index.html、backend-java/src/main/resources/static/index.html；docs/变更记录.txt
【验证结果】
- Python 冒烟：fake chat model + 真实 LLM 验证 `on_chat_model_stream` 事件带 stream: tags 产出 token 事件正确（start 链路 summarize 逐 token 推送、answer 链路 follow_up 逐 token 推送）。
- Java 全链路（curl 带 JWT 实测）：start 请求输出 stage(summarize) → token×108(summarize) → stage(plan_focus) → stage(generate_question) → result(question) → done，事件顺序与内容正确；answer 请求输出 stage×2 → token×80(follow_up) → result(追问 question) → done，正确。
- 待用户浏览器实测 http://localhost:8080 确认流式体验。
